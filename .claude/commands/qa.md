Ты — **Composer** QA-пайплайна. Ключ задачи: **$ARGUMENTS**.

Сначала проверь [project.md](../../project.md): если `status: not-configured` — не запускай
пайплайн, предложи пройти настройку по [START-HERE.md](../../START-HERE.md).

Иначе выполни шаги строго по порядку, не пропуская. Полные правила — CLAUDE.md и runbooks.

## 1. Прочитать задачу
Как указано в project.md (`tracker`):
- `jira-mcp` — тулзами чтения Atlassian MCP: задача $ARGUMENTS, описание, ВСЕ комментарии,
  связи, вложенные подзадачи. Только чтение.
- `paste` — попроси пользователя вставить описание и все комментарии задачи, если он ещё
  этого не сделал.

## 2. Собрать дифф
По [runbooks/collect-diff.md](../../runbooks/collect-diff.md): каждый репо из project.md —
`fetch`, найти ветку/коммиты задачи, дифф относительно `origin/<base_branch>`.

## 3. Анализ лупами (fan-out) — ты спавнишь их сам
По [runbooks/analyze-lenses.md](../../runbooks/analyze-lenses.md): запусти **параллельно**
всех суб-агентов-луп (read-only, модель из `lens_model`), одним заходом. Каждой — ключ,
текст задачи и способ получить дифф; каждая видит ВЕСЬ дифф и возвращает структурные
находки. Собери находки всех.

## 4. Синтез чек-листа (это делаешь ТЫ)
По [runbooks/generate-checklist.md](../../runbooks/generate-checklist.md): на входе задача +
**сырой дифф** + находки луп. Дедуп, сверка каждой находки с диффом, отбраковка ложных.
Не хватает доменного знания — спроси пользователя пачкой и сохрани ответ в `wiki/`.
Сохрани `checklists/$ARGUMENTS.md`, покажи в чате короткую сводку.

## 5. Опубликовать
Только если в project.md `publish: git` — по разделу «Публикация» в CLAUDE.md.
**В Jira ничего не писать.**
