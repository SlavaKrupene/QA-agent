# QA-агент: чек-листы с тест-кейсами по задаче и диффу

Агент на Claude Code. Даёшь ему ключ задачи из Jira, он:

1. читает задачу со всеми комментариями;
2. берёт из git реальные изменения кода по этой задаче (дифф);
3. натравливает на дифф 6–7 параллельных «луп» — суб-агентов, каждый ищет своё:
   баги, регресс, негатив и границы, данные и совместимость, расхождения задачи с кодом,
   покрытие тестами, платформенные особенности (для мобилки — жизненный цикл, разрешения,
   версии ОС, обновление поверх старой версии);
4. сверяет их находки с кодом и пишет `checklists/<KEY>.md` — план проверки из тест-кейсов
   (`TC-…`: приоритет, тип, предусловия, шаги, ожидаемый результат, зацепки для автотестов);
5. по желанию — второй фазой прогоняет этот план на стенде/устройстве и дописывает в тот же
   файл факты: PASS / FAIL / SKIP с цифрами, баги, вердикт.

Главная идея: **чек-лист строится по коду, а не по пересказу задачи**, и каждое утверждение
чем-то подтверждено. Всё, что в задаче написано иначе, чем сделано, — отдельным разделом.

Jira агент **только читает**. Комментарии в задачи он не пишет — чек-лист остаётся файлом,
переносишь его сам.

## Как начать

Нужно: Claude Code (приложение Claude во вкладке Code или терминал), git, доступ к
репозиторию приложения, Jira.

1. Забери репозиторий к себе — любым способом:
   - проще всего: на странице репозитория на GitHub кнопка **Code → Download ZIP**,
     распакуй и назови папку `qa-agent`;
   - или через git: `git clone https://github.com/SlavaKrupene/QA-agent.git qa-agent`
     (репозиторий приватный — GitHub спросит логин; если не пускает, скачай ZIP).
2. Открой папку `qa-agent` в Claude Code как проект.
3. Напиши Claude: **«Прочитай START-HERE.md и настрой»** (или команду `/qa-setup`).

Дальше Claude сам разберётся, что это, посмотрит твой репозиторий, задаст вопросы пачкой
(где лежит код, какой адрес у Jira, как вы тестируете) и всё настроит.

После настройки чек-лист по задаче: `/qa MOB-123` (подставь свой ключ).
Прогон готового чек-листа: `/qa-run MOB-123`.
Не нравится, как пишет, — `/qa-adapt` (или просто скажи Claude, что хочешь иначе).

## Что внутри

| Путь | Что это |
|---|---|
| `START-HERE.md` | инструкция настройки — её выполняет Claude |
| `CLAUDE.md` | правила проекта, Claude читает их сам при каждом запуске |
| `project.md` | профиль твоего проекта: репо, ветки, стек, Jira. Заполняется при настройке |
| `runbooks/` | процедуры: сбор диффа, лупы, правило чек-листа, прогон |
| `stack-hints/` | подсказки «куда смотреть в коде» под разные стеки (Android и общий) |
| `checklists/` | результаты, плюс `EXAMPLE-42.md` — пример готового чек-листа |
| `wiki/` | база знаний агента о твоём продукте — копится сама, из ответов на вопросы |
| `.claude/` | команды `/qa`, `/qa-run`, `/qa-setup`, `/qa-adapt` и запрет на запись в Jira |

## Про лимиты

Лупы работают на модели Opus, 6–7 штук параллельно, и каждая читает весь дифф. На большой
задаче это заметный расход. Если упираешься в лимиты подписки — в `project.md` поменяй
`lens_model` на `sonnet`.
