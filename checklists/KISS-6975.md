# KISS-6975 — [Client] Авторизация. Запасные способы входа на телефонах расходятся с ответом бэка

Список кнопок на стартовой странице (экране входа) по-прежнему приходит с бэка. Меняется только
поведение без ответа бэка и кэш списка. На Android и iOS запасной список теперь совпадает с бэком:
при русском языке остаются Google и Apple, VK добавляется ещё и по стране (RU/UA/KZ/BY). Язык
берётся из приложения, а не из системы. Кэш списка хранится отдельно на каждую пару «язык
приложения — регион». Если бэк не ответил, показывается последний ответ бэка для той же пары
любой давности, и только без него — список из конфига. Чего в диффе нет: перезапроса списка на
открытом экране (после смены языка на нём или после возврата сети) и учёта страны по IP в ключе
кэша. Бэкенд не менялся.

## Расхождения с задачей

1. **«Веб и Telegram не меняются» — верно только для списков конфига.** Кэш по паре «язык-страна»
   и запасной путь «сначала последний ответ бэка любой давности, потом конфиг» общие для всех
   платформ. На вебе без бэка теперь может показаться прошлый ответ бэка (например, с Google при
   русском языке браузера), а не список KISS-6565. Источник: `auth_types_repository.dart:41-80` —
   ветка по платформе есть только в `defaultAuthTypes`.
2. **Экран «Данные авторизации» (привязка соцсетей) тоже получил новые запасные списки** — в
   задаче не упомянуто. Экран берёт тот же список и оставляет из него Google (не веб), Apple (iOS)
   и VK. Пример без бэка: язык ru — теперь VK и Google (+ Apple на iOS), раньше только VK.
   Источник: `auth_settings_bloc.dart:32-36, 153-155`.
3. **Пустой ответ бэка обрабатывается так же, как отсутствие ответа.** 200 с `sources: []` или
   только с неизвестными источниками → последний ответ бэка, затем конфиг. В задаче сказано
   только «если бэк не ответил». Источник: `auth_types_repository.dart:58-63`, тест «пустой ответ
   бэкенда тоже сначала берёт просроченный ответ».

### Грабли окружения

- 🪤 **Выход из аккаунта кэш списка не чистит.** Ключи `persistent_auth_types_cache:<язык>-<страна>`
  переживают logout и «Save» на дебаг-экране (`CommonLocalStorage.clear()` не трогает
  `persistent_*`). Для проверки запасного списка — только системное «Очистить данные» (Android) или
  переустановка (iOS).
- 🪤 **После выхода из аккаунта и перезапуска язык приложения сбрасывается на язык системы.**
  Настройка языка хранится без `persistent_` и стирается логаутом. Не выходить из аккаунта между
  сменой языка и перезапуском.
- 🪤 **Подмена региона на дебаг-экране переживает logout.** После проверок вернуть Country и
  Accept-Language в «None». Системная очистка данных сбрасывает её тоже.
- 🪤 **Приложение запрашивает список сразу после старта, ещё до экрана входа** (`app.dart:178`).
  Для проверки чистого конфига авиарежим включать до запуска приложения, иначе в кэш ляжет ответ
  бэка.
- 🪤 **Без VPN шаг 4 из задачи ничего не доказывает.** Для одних и тех же языка и региона
  запасной список телефона совпадает с ответом бэка. Отличие видно, только когда IP-страна не
  совпадает с регионом телефона — для этого B4 с VPN РФ.
- 🪤 **Перевод часов назад после шага +2 дня оставляет кэш «свежим».** Если на +2 днях была сеть,
  слот получит метку из будущего и ещё ~2 суток не будет перезапрашиваться. После B4 — очистить
  данные. Сдвиг даты — по [wiki: adb-progon-na-telefone](../wiki/processes/adb-progon-na-telefone.md).
- 🪤 **В авиарежиме запасной список появляется почти сразу** (у запроса нет ретраев). Через
  «молчащий» прокси — до 9 с скелетона.
- 🪤 **Google может пропасть из списка по другой причине.** Если не инициализировался Google
  Sign-In, кнопка убирается независимо от списка (`auth_bloc.dart:133-150`, лог
  `Ошибка при инициализации Google авторизации`). Это не дефект этой задачи. Бывает ли это в
  авиарежиме — не проверено.
- 🪤 **Страна на stage — по IP.** С машины агента 12.10.2026 IP-страна BG: язык en без подмены
  даёт список без VK. Регион телефона на ответ бэка не влияет.

### Грабли прогона (2026-10-13)

- 🪤 `pm clear` сбрасывает и язык приложения, заданный через `adb shell cmd locale set-app-locales`. Задавать язык после
  очистки.
- 🪤 Язык и регион «как у устройства» удобно менять без системных настроек:
  `adb shell cmd locale set-app-locales gg.playneta.kiss2 --user 0 --locales en-KZ` (сброс — `--locales ""`). Flutter

- 🪤 IP этого телефона (Wi-Fi `RT-…`) сервер считает «VK-страной»: онлайн VK есть при любом языке. Встроенный
  список без VK виден только без сети.
- 🪤 Дебаг-экран долгим нажатием через `adb input swipe` / `motionevent` не открылся. Подмену страны заменил регионом
  приложения.
- 🪤 Без свежего кэша на каждый запуск уходят два одинаковых `GET /login/availability` (предзагрузка и экран). Это не
  дубль-баг.
- Google в авиарежиме не пропадает: инициализация Google Sign-In без сети проходит.

## Границы фичи

- Список на открытом экране не обновляется ни после смены языка на нём, ни после возврата сети.
  Для гостя экран входа корневой, поэтому новый список появится только после перезапуска
  приложения. Смена языка вынесена в «Не входит», возврат сети в задаче не упомянут.
- Порядок кнопок на экране не совпадает с порядком списка в задаче.
  - Первая кнопка во всю ширину — Google на Android, Apple на iOS.
  - Остальные соцсети и почта идут рядом иконок, если их 2 и больше; одна — кнопкой с текстом.
  - Гость — отдельная кнопка внизу.
  - VK в ряду — пара иконок VK/OK.
  Проверяем набор кнопок, не порядок.
- Ключ кэша — язык приложения и регион телефона, а бэк смотрит на страну по IP. После смены IP
  (VPN, поездка) до суток показывается прежний список, без сети — сколь угодно долго. Задача это
  признаёт частично: «в нём учтена страна по IP».
- Изменение общее для всех Android-флейворов (kiss2, rooms, lovium, gozo, kiss1, among, luv) и
  iOS-флейворов (kiss2, rooms, kiss1): списки от флейвора не зависят.
- Старый кэш (до обновления) не читается: первый запуск новой версии без сети покажет список из
  конфига.

## Открытые вопросы

1. Прошлый ответ бэка показывается без сети сколь угодно долго (`ignoreTtl: true`, верхнего
   предела нет). Так задумано, или нужен потолок — например, неделя?
2. На вебе и в Telegram тоже включены кэш по «язык-страна» и правило «сначала прошлый ответ
   бэка». Это осознанно, раз в задаче сказано «веб и Telegram не меняются»?
3. `AuthStorage.loadAuthTypesFromCache` разбирает имена через `firstWhere` без `orElse`. Теперь
   это чтение стоит и в `catch`-ветке запасного пути: неизвестное имя в кэше оставит экран входа
   на скелетоне (`AuthBloc._init` без try). Добавить `orElse` или фильтр неизвестных?
4. Ключ кэша — регион телефона, а бэк смотрит на IP. После смены IP (VPN, поездка) пользователь
   до суток видит прежний список онлайн. Это приемлемо?
5. Со слов команды, смысл задачи — «при упавшем бэке показывается дефолтный экран входа». По коду
   дефолтный (запасной) список показывается, только если нет сохранённого ответа бэка для тех же
   языка и страны. Если он есть — показывается он, любой давности. Так и задумано?
6. Какие 42 сочетания «язык × страна» сверялись со stage? Их можно превратить в табличный
   автотест против `AvailableRegistrationSources`.
