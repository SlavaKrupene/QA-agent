# Runbook: собрать дифф по задаче

Цель: по ключу задачи найти изменения кода и подготовить дифф для анализа. Bash + git по
локальным копиям репозиториев из [project.md](../project.md). MCP здесь не нужен.

## Вход
- Ключ задачи, например `MOB-123`.
- Текст задачи с комментариями (шаг 1 пайплайна). Имя ветки часто называют именно в
  комментарии («ветка feature/MOB-123-login») — поэтому комментарии читаем всегда.
- Из project.md: список репо, `base_branch`, `branch_pattern`, `commit_pattern`.

## Шаги
Для **каждого** репо из project.md; в итоговый дифф включить те, где задача нашлась.
Одна задача может жить в одном репо, в нескольких или ни в одном — это нормально.

1. Актуализировать — всегда:
   ```sh
   git -C <repo> fetch --all --prune
   ```
2. Найти ветку задачи:
   ```sh
   git -C <repo> branch -r | grep -i "<KEY>"
   ```
   Несколько веток (например, `feature/…` и `bugfix/…`) — взять ту, что названа в задаче
   или обновлялась последней, и сказать об этом строкой в «Контексте» чек-листа.
3. Ветки нет — поискать коммиты по ключу (задача могла быть уже влита или жить в общей ветке):
   ```sh
   git -C <repo> log --all --oneline --grep="<KEY>"
   ```
   Нашлись коммиты в базовой ветке — дифф собирать по ним (`git show <sha>` на каждый или
   диапазон от первого родителя до последнего).
4. Ветка есть — переключиться и подтянуть, если рабочее дерево чистое:
   ```sh
   git -C <repo> status --porcelain          # пусто = чисто
   git -C <repo> checkout <branch>
   git -C <repo> pull --ff-only
   ```
   Дерево грязное (у пользователя там свои правки) — **не трогать**: не переключаться,
   работать по `origin/<branch>` через `git show` / `git diff`, сказать об этом одной строкой.
5. Коммиты задачи относительно базы:
   ```sh
   git -C <repo> log --oneline origin/<base_branch>..origin/<branch>
   ```
6. Дифф — три точки, от точки расхождения с базой (иначе в дифф попадут чужие изменения,
   влитые в базу после отведения ветки):
   ```sh
   git -C <repo> diff --stat origin/<base_branch>...origin/<branch>   # обзор
   git -C <repo> diff        origin/<base_branch>...origin/<branch>   # полный
   ```

## Если дифф большой
- Сгенерированное и шум отфильтровать из чтения, но упомянуть в «Контексте»: lock-файлы,
  сгенерированные схемы/ресурсы, бинарники, массовые переименования.
- Читать всё остальное **целиком**. Не дочитал — в чек-листе строка «Контекст» получает ⚠️
  с тем, что именно не дочитано.

## На что обратить внимание (вход для чек-листа)
- Логика — основной предмет проверки.
- Новые/изменённые тесты — что разработчик уже покрыл (руками не дублируем), что нет.
- Хранилища и совместимость: миграции локальной БД, схемы, настройки, API-контракт.
- Конфигурация: фиче-флаги, remote config, build-переменные, манифест, разрешения.
- Документация и план реализации в репо, если есть: сверить замысел с фактом.
- Для мобилки и вообще — ищи по таблице «Куда смотреть в коде» в project.md.

## Безопасность
- Только чтение репозиториев; никаких commit / push / reset / правок файлов.
- Не печатать `.env` и секреты, даже если они попали в дифф. Попали — отметить в «Баги»
  как утечку секрета, само значение не цитировать.
