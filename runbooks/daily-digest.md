# Ежедневный дайджест задач в разработке

Зачем: каждое утро видеть все задачи KISS, которые разработчики взяли в работу, чтобы
распределять их между тестировщиками и заранее решать, какой задаче нужен ранний разбор.

Скрипт — [scripts/jira-digest.py](../scripts/jira-digest.py). Jira только читает (в коде есть
только GET). Тестировщиков в Jira назначает пользователь сам; агент поля не меняет (R1).
Файлы дайджеста лежат в `digests/` и в git не идут.

## Шаги

1. `python -I scripts/jira-digest.py collect` — факты из Jira в `digests/<дата>.json`.
   «Новые» считаются от прошлого запуска (`digests/.state.json`); первый запуск смотрит на
   один рабочий день назад (в понедельник — с пятницы).
2. Прочитать `digests/<дата>.json` и записать `digests/<дата>.summaries.json` по правилам ниже.
3. `python -I scripts/jira-digest.py render` — итоговый `digests/<дата>.md` (всё таблицами).
   Скрипт печатает короткую версию для чата: таблицу показателей и таблицу новых задач.
4. В чат — ссылку на `digests/<дата>.md` и эти две таблицы как есть, без пересказа текстом
   (пользователь просил таблицы: текст читается хуже). Ниже таблиц — не больше 2 строк,
   только если есть что-то срочное: задача давно в работе или явный кандидат в ранний разбор.

## Тестировщик «по умолчанию»

Jira ставит в «Тестировщик» человека по умолчанию (`DEFAULT_TESTERS` в скрипте; сейчас —
Радмир Ахметьянов, скоро будет сама пользователь). Это ещё не решение: часть таких задач
пользователь оставит себе. Дайджест помечает их «(по умолч.)» и никуда не переносит —
распределяет пользователь. Сменился человек по умолчанию — поправить `DEFAULT_TESTERS`.

## Краткие описания (`summaries.json`)

Формат — объект по ключу задачи, для каждой задачи из `in_development` и
`in_testing_without_tester`:

```json
{"KISS-1234": {"gist": "…", "qa": "…"}}
```

- `gist` — суть в 1–2 коротких предложениях простым языком: что меняется для игрока или для
  системы. Источники — только поля задачи: `summary`, `description`, `last_comments`,
  `parent`, `links`. Не выдумывать. Если описания нет — суть по заголовку и родителю, с
  пометкой «по заголовку».
- `qa` — одна короткая фраза для распределения:
  - объём проверки `S` / `M` / `L` и что проверять (экран, платформа, бэк);
  - или «тестировать нечего — ресерч / документ / разовая операция»;
  - или «кандидат в ранний разбор: есть ТЗ / крупная фича».
  Объём — оценка, а не факт; при сомнении писать «оценка неуверенная».
- Без ссылок, uuid игроков, e-mail и токенов. Ссылки на задачу дайджест ставит сам.
