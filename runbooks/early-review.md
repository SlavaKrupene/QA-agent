# Ранний разбор задачи до кода — `/qa-early <KEY>`

Когда: разработчик только взял задачу в работу, кода по ней ещё нет или он не готов.
Цель: к моменту «К тестам» иметь ответы продукта, план проверки и готовый стенд.
Отличие от `/qa`: без луп и без диффа, один исполнитель, бюджет ~40 вызовов инструментов.
Модель — opus (закреплена в `.claude/commands/qa-early.md`): на KISS-7051 sonnet был дешевле
(2,5M токенов против 3,8M, ~6 мин оба), но пользователь выбрал opus по качеству разбора.
Когда код появится, `/qa <KEY>` строит полный чек-лист и берёт этот черновик на вход.

Правила те же, что у пайплайна: Jira и Confluence только читаем (R1), репозитории приложения
только читаем, stage не трогаем — ранний разбор только читает. Секреты не выводим.

## Шаги

1. **Задача.** `jira_get_issue <KEY>`: описание, все комментарии, связи, родитель. Есть
   эпик — `jira_search "parent = <эпик>"`, чтобы увидеть парные [Client]/[Server] задачи.
   Ссылка на Confluence в задаче или в эпике — `confluence_get_page`. Ссылку на Figma только
   записать: внешний вид сверяет `/qa` (R6).
2. **Тип разбора** — от него зависят разделы файла:
   - **A — фича с ТЗ**: вопросы по ТЗ, как сейчас работает соседний код, черновик проверок;
   - **B — баг**: где в коде, гипотеза причины, шаги воспроизведения до фикса;
   - **C — техдолг, оптимизация, доработка без ТЗ**: кто использует меняемый код (это и есть
     регресс), что замерить «до»;
   - **D — ресерч, документ, разовая операция**: 3–5 строк «что тестировать после» и стоп.
3. **Код как есть сейчас** — базовая ветка, не ветка задачи. Репозитории — из
   [project.md](../project.md); нужного нет — `gh search code --owner playneta <слова>`,
   клонировать в `repos/` (`gh repo clone playneta/<repo> -- --filter=blob:none`). Найти
   место, которое будут менять, и кто его использует: ручки, топики Kafka, DTO из `pkg`,
   клиент. Ветка задачи уже есть — одной строкой «код уже пишется», дифф не разбирать.
4. **Записать** `checklists/<KEY>.early.md` по формату ниже. В чат — таблица: тип, объём
   S/M/L, число вопросов, главный риск.

Не хватает доменного знания — сначала [wiki/index.md](../wiki/index.md). Вопросы
пользователю не задавать по ходу: всё неясное — в раздел «Вопросы», его отправляет пользователь.

## Формат `checklists/<KEY>.early.md`

Таблицы там, где строк больше двух: пользователь читает таблицы лучше текста.

```markdown
# <KEY> — <заголовок> · ранний разбор

| Статус | Тип разбора | Разработчик | Тестировщик | Объём | Дата |
|---|---|---|---|---|---|

Источники: что прочитано (задача, N комментариев, ТЗ, репозитории с коммитом базы).

## Суть
2–4 предложения простым языком: что меняется для игрока или системы.
```
