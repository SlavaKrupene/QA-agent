# Wiki проекта — схема (метод Карпати / LLM Wiki)

База знаний QA-агента о продукте и процессах — о том, чего **нет в коде**. Обычный markdown
для LLM с длинным контекстом: без БД, поиска по эмбеддингам и прочего. Агент читает
`index.md`, находит нужные страницы и читает их напрямую.

Этой вики **владеет агент**: создаёт и обновляет страницы. Не путать с документацией внутри
репозитория приложения — ту агент только читает.

## Главный принцип: не копировать чужое

Здесь только **новое знание**, которого нет ни в коде, ни в документации репо: то, что
узнали от человека; договорённости команды; продуктовые правила; связи между частями
системы, которые нигде не записаны. Если факт уже есть в коде или доках — читаем оттуда,
сюда не дублируем (можно сослаться: «детали — в `<repo>/docs/<page>`»).

## Слои

1. **`raw/`** — неизменяемые источники: вставленные спеки, выгрузки, описания API. Агент
   читает, но не правит. Необязательно: основной источник — ответ человека в чате, его
   можно сразу превращать в страницу.
2. **Страницы** — ими владеет агент:
   - `index.md` — каталог всех страниц, одна строка на страницу;
   - `log.md` — журнал, только дописывать: что узнали, когда, из какой задачи;
   - `overview.md` — карта продукта верхнего уровня;
   - `concepts/` — понятия продукта (как устроена подписка, что такое «активный пользователь»);
   - `entities/` — сущности (роли, тарифы, внешние сервисы, типы устройств);
   - `processes/` — процессы и договорённости (как тестируем, как готовим стенд, кто что решает).
3. **Схема** — этот файл.

## Формат страницы

Файл `<topic>.md` в подходящей папке, имя — kebab-case:

```markdown
---
title: Пробный период подписки
summary: Одно предложение — чтобы по index понять, нужна ли страница.
tags: [subscription, billing]
updated: 2026-09-12
sources:
  - задача MOB-123, ответ пользователя в чате
---

<суть: правила, числа, исключения>

## Связано
- [[subscription-plans]]
- [[store-billing]]
```

Связи — `[[slug]]` (имя файла без `.md`). Ссылка на ещё не созданную страницу допустима —
это пометка «завести позже».

## Операции

- **Ingest.** Узнал факт о продукте: проверь `index.md` — есть близкая страница? Дополни её,
  не плоди дубль. Нет — создай. Обнови связи `[[…]]`, строку в `index.md`, запись в `log.md`
  (`## <дата> — <KEY>: <что узнали>`).
- **Query.** При чек-листе: `index.md` → нужные страницы → используй. Не нашёл — порядок
  устранения пробелов в runbooks/generate-checklist.md.
- **Lint.** Иногда: противоречия между страницами, страницы без входящих ссылок, устаревшее,
  битые `[[ссылки]]`. Чинить по согласованию с пользователем.

## Что НЕ писать

- Пересказ кода и документации репо.
- Секреты, токены, пароли, личные данные реальных людей.
- Сиюминутные детали одной задачи, бесполезные в будущем.
